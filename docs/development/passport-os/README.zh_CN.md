# Passport 电子工牌

本分支开机直接显示可编辑电子工牌。Mac 的青笺应用集中编辑姓名、职位、介绍、三阶段图片、两次进化门槛和功能展示选择。设备提供 CW2017 实际电量、同步后的本地时间、Codex 额度看板和可玩的 Dino。USB 与加密蓝牙使用同一套应用协议，不启动 Wi-Fi 或音频。

## 使用

- 设备开机并连接 USB，打开 Mac 的青笺应用；也可明确选择此前已配对的蓝牙设备。编辑并上传，以设备回读一致作为保存成功依据。
- 默认三形态为围巾、红裙魔法使、红发青子，默认门槛为 77,777,777 和 555,555,555 Token；两次门槛与每个阶段图片都能独立修改。
- 快速连按三下 OK 熄屏；任意功能键的完整手势只负责唤醒。上下切换可见页面，长 OK 返回。独立硬件电源键保持原有功能。
- 连按间隔按 350 毫秒判断，长按为 800 毫秒。熄屏关闭背光，处理器仍运行，不等于深度睡眠。
- 时间通过所选连接，以 Mac 的 UTC 和本地时区偏移为锚点。完全断电重启后需要重新同步；断开连接不影响本次开机的时钟继续走时。

## 蓝牙连接

通过设备设置或可信 USB 的 `PAIR` 命令打开 120 秒配对窗口。首次配对时，设备显示六位配对码，在 Mac 的蓝牙提示中输入该码。加密 BLE 服务负责配对和绑定；打开窗口或收到 `PAIR_OK`，不代表 Mac 已完成配对。

广播名称为 `QingJian-` 加 MAC 末六位十六进制数字。Mac 应用扫描候选后，必须由用户选择设备或使用已保存的 macOS 外设 UUID；名称相同不能代替身份认证。macOS UUID 是该 Mac 使用的外设标识，固件的 `device_id` 则是跨 USB、蓝牙保持一致的 base MAC 标识。切换连接不会开始新的 Token 周期或重复播放进化动画。

NUS 服务为 `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`；RX 为 `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`，用于写入；TX 为 `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`，用于通知。主机先订阅通知再发送命令，按协商的 MTU 分片，同一时刻仅发送一条待确认请求。接收行有长度上限；断线丢弃未完成消息与传输状态，响应只返回所属的连接与会话。超时后不自动重发可能修改设备的命令。

Mac 后端在整个蓝牙会话内使用同一个 asyncio 事件循环。首次连接设有 60 秒期限，包含发现设备与输入配对码的时间；同步适配层另留断开清理时间。蓝牙同步时间、Token、额度、文字和设置；所有头像写入（包括恢复默认图片）均需要 USB。蓝牙配对与使用已通过本地用户验收；USB 图片上传、回读、重启保存、恢复默认、多次无重置重连及保护区复读也已验证。新增看板回读仍是独立的验收项目。

## Codex 额度看板

看板只使用主 Codex 额度桶，按实际来源显示零、一或两个窗口。账户只返回周窗口时，不额外画出不存在的五小时窗口。每个可用窗口显示真实时长、重置时间和剩余百分比，剩余值按 `clamp(100 - usedPercent, 0, 100)` 计算；缺失、非法或不可用数据保持未知。不用 Spark 等其他模型额度替代主额度桶。

优先来源是只读 Codex App Server 额度接口，本机 Token 日志中的额度快照作为明确标注的回退来源。来源和过期状态始终可见。有效期依据源观测时间，最长 180 秒，必要时在额度窗口重置时提前过期。重发缓存或在另一条 Token 事件中再次看到同一快照，都不会延长有效期。时钟回拨、缺少时间或已过期的数据不能显示为新鲜数据。

额度百分比与本机统计的 Token 活动是两个独立指标。此看板不修改订阅、不购买额度，也不兑换重置卡。

## 本地数据源与智能体看板

青笺 1.2.0 新增 Cursor/Gemini 本地计数与智能体页，分别显示 Codex、Cursor、Gemini 活动。Mac 在同步前检查 `provider_dashboard_supported`。活动状态与累计计数各自保留源时间；工作状态最长 180 秒过期，累计计数则保留其原始观测时间。缺失、记录不完整、未来时间和过期会明确显示。进程存在、已登录或历史 Token 数都不能单独证明任务正在运行。

- Cursor 统计本机代码追踪数据库中的去重请求，只覆盖该记录中的代码活动，不等于全部对话次数、Token、个人额度或账单。生命周期状态来自 [Cursor 官方 hooks](https://cursor.com/docs/hooks)。本机 CLI 请求与真实 `sessionEnd` 事件已验证。
- Gemini 读取本机 Gemini CLI 模型记录中的 Token 元数据，并接收 [官方 CLI 生命周期 hooks](https://geminicli.com/docs/hooks/reference/)。不覆盖 Gemini 网页、App、Antigravity 或全账户额度。当前个人 CLI 验收请求被服务端拒绝，没有新增 Token；接收器安装和历史日志可读不能证明在线服务完全连通。
- Codex 活动通过私有增量索引读取实际任务开始、完成和中止事件。Token 事件只能续期已经观测到的活动任务，不能自行创建工作状态。覆盖不完整时不推断空闲或总会话数；有新鲜阳性任务事件时仍可显示工作中、等待或错误，总数保持未知。索引处理 fork 继承、替换任务、文件轮转和截断。
- Grok Bot 已从功能选项、工牌页面与数据源设置中移除。旧协议位仍保留，既有设置的标识不会移位；独立的 Mac 应用保持原样。

经授权安装的 hook 接收器只向私有应用支持目录写入匿名会话/轮次哈希、状态、时间及受限模型标签，不保存提示词、回复、源路径、邮箱或凭据。安装合并原有 hooks 数组与设置并保留备份。Mac App 移动后，下次启动只更新已安装的解释器映射，不为新用户静默安装 hooks。Codex 活动数据库是接收端自己的索引，不修改来源日志。

智能体概览与页面列表使用相同的功能选择：取消 Gemini、Cursor 或 Codex 后，对应活动状态也不再出现。保留行紧凑排布，不留空位；未选择任何 AI 来源时，提示前往 Mac 功能设置。重新启用全部支持项后，恢复三个来源。

## Dino

游戏使用 [Chromium 98.0.4758.55 原版精灵图集](../../../assets/dino/README.zh_CN.md)，包含恐龙、仙人掌和飞鸟，保留 BSD 许可证及可复现转换。原版造型和操作已通过用户实机确认；这是设备适配版，不承诺浏览器帧率。

UP 起跳，按住 DOWN 下蹲，松开 DOWN 结束下蹲。短按 OK 暂停或继续，长按 OK 退出游戏。三连 OK 熄屏并暂停本局，唤醒后的第一个完整手势只用于亮屏。暂停、退出和熄屏时通过最高分保存流程提交新纪录，不在每帧写入闪存。后续固件变更仍需回归最高分保持与实物按键时序。

碰撞判定采用仓库所附 Chromium 98 的 `checkForCollision`、`Trex.collisionBoxes` 与原版障碍定义中的固定身体碰撞框，振翅的翅尖不作为伤害区域。这修复了中层飞鸟偶尔使持续下蹲直接进入撞击状态的问题；中层和高层飞鸟的所有动画阶段均可下蹲通过，低层飞鸟仍需跳跃。主机回归覆盖下蹲与振翅组合的完整 60 帧周期、828 分最高速度下的完整穿越、低飞鸟可跳过及最高分保留。更新后的飞鸟行为仍须单独实机验收。

## Token 周期与进化

仅索引本机可读取的 Codex 用量事件，包含缓存输入与输出；累计事件和同会话副本不重复相加，排除 fork 继承部分。这不等于账单、额度百分比或全账户总量。当前周期数据尚未扫描完整时显示未知。

官方 Codex 主额度桶的周窗口用于识别周期，自然周重置后重新计数。当前接口没有可靠的重置卡已使用事件：使用重置卡后，请在应用中明确确认。该按钮只重设工牌计数起点，不购买或兑换重置卡。账户变化、数据源失败和过期会分别显示。

已知用量从低于最终门槛向上跨越且工牌页可见时播放短变身动画；已在高阶重连、开机、USB 切到蓝牙或单纯修改门槛不重复播放。Mac 应用保持打开，通过所选连接同步新增用量。独立 Coding Pet 桌宠功能已取消，工牌头像进化仍保留。

## 保存与硬件边界

资料、门槛和功能选择保存在普通 NVS。设备缓存一张带阶段编号的自定义图片；Mac 保存三个阶段的选择，并通过 USB 在对应 Token 更新之前传入当前所需图片。蓝牙同步不会替换或清空缓存：需要更新时返回 `avatar_sync=usb_required`，时间、Token 和额度继续同步。进入另一自定义阶段时需连接 USB 安装该阶段；三张自定义图片并非全部常驻工牌。编辑器可离线保存草稿，自动同步不会提前应用尚未提交的草稿。

新图片使用固定 8,224 字节的 `APZ1` 数据包，由 16 字节小端 `<4sHHII` 文件头、zlib 压缩的 RGB565 像素及补零组成。编码器从 128、112、96、80、64、56 中选择能够容纳的最大正方形分辨率；安装前校验尺寸、压缩与解压长度、压缩流完整性，再放大到固定 128×128 显示缓冲。内置图片保持完整 128×128 RGB565，旧索引色仅作为兼容读取路径。

透明原图等比完整放入正方形并合成黑底，不裁掉人物身体。Mac 像素预览使用与设备相同的 RGB565 转换和最近邻映射；新上传保留 RGB565 色彩，不再缩减到 16 色调色板。

保存失败不会擦分区；提交后若未确认应用状态，会明确报告保存未确认，之后回读或重启可能看到已提交的数据。

保留电量计既有 profile。只读接入检查工作状态及既有 profile 标志，不代表电芯精度已标定；未知电量显示横线。本项目不需要改引脚、分区、启动器、身份或恢复布局。

已有设备先完整备份并核对实际分区。确认兼容后仅写入 0x10000 应用区，禁止整片擦除。个人闪存备份和日志应保存在源码及社区包之外。

## 开发

基于官方 main `f75873f1aab24ac4c0ba9394c131669f66cce650`、ESP-IDF 5.5.3、ESP32-C3、8 MB、无 PSRAM。执行 `tools/validate.sh --static`、`--firmware` 和完整检查。主机测试覆盖手势互斥、功能子集、保存格式、时间、进化门槛、Token 统计、额度时效、Dino 逻辑、APZ1 解码、上传回读和 BLE 传输行为。主机测试也覆盖 hook 隐私/时效、数据源索引和计数来源。编译、主机测试与真机结果必须分开报告；后续 App 重新构建不自动代表新增看板已验收。

保留五项为 Codex、Cursor、Gemini、智能体和 Dino（支持掩码 `0x97`）。本地数据源看板已在上述来源边界内实现；Gemini 当前个人 CLI 的服务端拒绝尚未解决。独立桌宠已取消，AI Talk 延后，iPhone 功能仍待后续开发。勾选页面不代表数据源已经连通。

## 后端与传输协议

`tools/passport_bridge.py` 共用 `status`、`sync`、`upload --config` 和 `screen 0|1`。全局 `--port` 指定 USB，全局 `--ble-id` 指定用户明确选择的 macOS UUID，两者互斥。`ble-scan` 只返回候选设备；`pair` 仅用于 USB 请求配对窗口；`preview-avatar --source --output` 只在本机处理图片，不连接设备。Mac 应用把已验证的后端配置放在应用支持目录的 `AI Passport/Bridge` 中；独立 CLI 若要共用该配置，应传入相同的 `--state-dir`。

两条连接都传输以换行结尾的 `@AP` 文本命令：

- `STATUS`、`TIME <utc_ms> <offset_min>` 和 `SCREEN <0|1>` 查询或更新基本状态。
- `BADGE <base64-json>`、`FEATURES <all> <mask>` 和 `THRESHOLDS <first> <final>` 修改偏好；排队成功的回执之后，还要回读已保存状态。
- `TOKENS <count|UNKNOWN>` 更新活动用量，不随周期同步反复写 NVS。确认新周期后先发零，再发新计数；单纯切换连接不会如此处理。
- `CODEX <base64-json>` 发送扁平额度快照，包含来源、观测与到期时间，以及两个实际窗口的可空字段；主机先检查固件能力，再使用该命令。
- `PROVIDER <base64-json>` 发送有界数据源快照，活动与计数各自保留时间。主机先检查 `provider_dashboard_supported`，收到回执后回读对应来源的更新 ID；覆盖缺失不能生成虚构计数或工作状态。
- 仅 USB 的 `AVATAR BEGIN 8224 <sha256> <stage>`、连续的 `AVATAR DATA <offset> <base64>` 与 `AVATAR END` 安装校验通过的自定义图片；仅 USB 的 `AVATAR DEFAULT` 清除自定义缓存并恢复内置图片。蓝牙对所有 `AVATAR` 命令返回 `@AP ERROR avatar_requires_usb`；`STATUS` 声明 `avatar_upload_usb_only: true`。
- `PAIR` 经可信 USB 打开配对窗口，命令本身不代表系统配对完成。

服务凭据、账户邮箱和对话正文不会传给工牌。BLE 模块和可选依赖版本分别为 `tools/passport_ble.py` 与 `tools/requirements-ble.txt`；Mac 应用包需要蓝牙用途说明权限项，以及 CoreBluetooth、PyObjC 等运行时依赖。macOS 运行时 USB 使用 `tools/passport_serial.py`，不由应用切换 DTR/RTS，并关闭断开时挂起；烧录工具保留独立的复位流程。

## 在青笺内设置数据源

Mac 应用的「数据源接入」会分别检查配置完整性和是否收到活动，再提供明确的配置/修复操作。Cursor 使用官方桌面 Agent / CLI 回调。Gemini CLI 回调与已安装的原生 Gemini Mac 应用分开标注；当前没有接通 Gemini Mac 的实时活动或 Token 接口。已配置不等于已登录、收到新活动或可读取订阅额度。

检测不连接工牌、不请求认证、不运行模型。设置会先校验全部选中配置，保留其他回调和设置，保存私有的原始字节备份，检查并发修改并回读写入结果。失败时只恢复仍属于本次写入的文件，保护用户期间的改动；不会默默覆盖已停用或自行调整的回调。

本地命令是 `sources-status` 与 `sources-configure --provider cursor`（或 `--provider gemini`）。应用使用内置运行环境；工牌本身的 USB / 蓝牙连接单独设置。

参考：[Cursor hooks](https://cursor.com/docs/hooks)、[Gemini 原生 Mac 应用](https://gemini.google/aw/mac/?hl=en)、[Gemini CLI hooks](https://geminicli.com/docs/hooks/reference/)。

## Cursor 账户额度与原生头像细节（2026-09-13）

Cursor 通过客户端内部只读 GetCurrentPeriodUsage/GetPlanInfo 接口读取当前已登录账户；这并非公开稳定 API。两组已用比例和账单重置时间与 Token 成长分开，凭证不缓存。额度最多五分钟过期，并按账户指纹隔离。USB/蓝牙传输规范化 CURSOR 摘要；Mac 构建 9 已包含收集器与两组用量显示。

青子原图未改动，直接转换为 Flash 中的原生 160×160 RGB565。Mac 默认高清原图预览，并提供单独的实际设备像素模式；自定义 128×128 编解码保持兼容。
